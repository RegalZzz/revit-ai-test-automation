# 业务接入与断言

## 接入生产服务

生成后先构建和运行默认 `api-smoke`，确认测试环境，再在 `TestScenario.Run(TestContext context)` 中接入目标业务。需要改动当前功能时保留用户已有逻辑。

添加真实项目引用到测试 csproj，并在场景中记录被测程序集：

```xml
<ItemGroup>
  <ProjectReference Include="..\..\YourPlugin\YourPlugin.csproj" />
</ItemGroup>
```

接入形态（类型和方法按项目实际 API 替换，以下不是通用可执行命令）：

```csharp
context.RecordAssembly(typeof(YourBusinessService).Assembly);
// 1. 用 context.Document 建立最小场景，并提交场景子事务。
// 2. 创建本轮设置，明确视图和作用范围，调用真实业务服务。
// 3. 通过 Revit API 重新读取结果；不要仅检查服务自己返回的成功标志。
// 4. context.Check(独立计算的条件, "可解释的业务断言");
// 5. context.ExportView(view, "after-operation");
```

更新 `TestScenario.Scope` 为实际测试范围。构建产物可能是项目引用输出，也可能在 Revit 中被已加载的同名程序集统一解析；以 `RecordAssembly` 记录的实际路径和 SHA256 为准，核对目标版本。发现旧 DLL 时在新进程中修正加载来源，不静默把源码版本当作运行版本。

服务为 internal 时优先沿用已有友元测试程序集或既有测试入口。不要仅为测试复制实现、改变业务默认值或大幅扩大 public API。

`IExternalApplication` 的回调没有可随意构造的 `ExternalCommandData`。不能通过 `new ExternalCommandData()` 假装执行正式命令。要验证 `IExternalCommand.Execute`，需要真实 Revit 命令调度或合法宿主测试入口，并有可等待的完成信号；这一层应另建验收，不能由服务测试替代。

## 构造场景

优先选能暴露规则的最小对象集：基础管段、分层管段、错误系统、隐藏/视图外对象、已有文字和标注、墙柱、链接障碍物。使用固定坐标、明确单位和可解释预期，必要时另加变换与边界场景。

- 所有主文档建模放在 Transaction 内；模板外层组负责最终回滚。
- 需要真实族连接器、文字字形或路由首选项时使用专用 fixture，不能以 DirectShape 替代后声称验证了这些语义。DirectShape 可用于适合其表达的几何障碍测试。
- CAD 用输入副本，明确导入单位和视图。按实际 API 读取变换，验证平移/旋转只应用一次。
- 链接模型在运行目录中创建或复制，独立保存临时 fixture；打开的辅助文档用 try/finally 关闭，不改原链接。
- Revit 内部长度单位为英尺，毫米换算为 `/ 304.8`；若使用版本相关 UnitUtils，适配正确 API。角度写清弧度/度；纸面距离结合视图比例验证。

## 断言应检查什么

| 场景 | 有意义的检查 |
| --- | --- |
| 族放置 | 数量、族/类型、位置与容差、旋转/镜像、标高、尺寸、不修改原类型 |
| 管路 | 各连接器实际 IsConnected/AllRefs 链、Owner、系统/管径、弯头/管段及无孤立残留；位置重合不等于连通 |
| 标注 | 两线一字等目标结构、角度、字线边缘关系、纸面间距、文字类型、避让对象、真实冲突输出 |
| 过滤 | 系统、类别、视图可见性、截面范围以及应排除对象 |
| 重跑 | 不重复生成、正确更新或清理本功能旧对象、保留其他功能及手工对象 |
| 非法输入/业务失败 | 明确失败结果、事务回滚、无半成品与孤立管段；不要仅断言抛出任何异常 |
| 参数/命令入口 | 普通 .NET 参数映射测试；真实服务验证模型变化；在合法 Revit 宿主上下文中另验收正式命令和界面入口 |

预期值不要从被测算法原样计算。用场景已知坐标、独立几何关系、实际参数或连接器查询形成检查。截图可以帮助审阅但不能代替上述断言。

## 与界面测试的关系

业务服务测试无需鼠标。WPF 控件测试可在 STA 线程中构造窗口、FindName 并设置属性或触发事件，但它只证明对应控件行为。

真正的 UI 测试优先使用环境可用的桌面自动化工具和稳定控件标识，并检查最终模型。需要用户完成安全提示时明确指出测试进程与提示内容。不要在没有工具时声称已点击，或把 API 导图说成屏幕截图。

## 报告格式

用简短事实说明：目标年份/Build、输入来源、实际加载的测试和业务 DLL、断言数量与核心场景、回滚/文件哈希、导图位置，以及未验证的正式命令或界面入口。超时后恢复完成的运行单独说明，其原始退出码保持原样。
